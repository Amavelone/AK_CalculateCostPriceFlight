# Монитор расчета себестоимости: baseline бизнес-логики

Статус: **implementation baseline v1.1**.

Назначение: этот документ — рабочая точка входа для программной реализации расчета и веб-интерфейса. Сначала система должна **точно воспроизводить действующие результаты Excel** на сценариях сверки. Целевой интерфейс затем сохраняет эту расчетную логику, но снимает ограничения Excel-экрана: предоставляет управление источниками, единый справочник услуг и произвольное число плеч.

## 1. Границы и приоритет источников

Монитор рассчитывает себестоимость маршрута из последовательности рейсовых плеч. Каждый расчет выдает три итоговых уровня маржи: `М1`, `М2`, `М3`. Их экономическая детализация не входит в специфику монитора и находится в зоне ответственности экономистов.

При конфликте источников использовать следующий порядок:

1. Подтвержденные владельцем процесса решения в этом документе.
2. Активные M-коды Power Query и формулы основной книги `Расчет себестоимости рейсов (1).xlsx` — эталон текущего вычислительного поведения.
3. [Технический анализ](cost-monitor-analysis.md) — доказательная инвентаризация, происхождение правил и список ограничений.
4. Исходные Excel-выгрузки — данные, но не самостоятельная интерпретация бизнес-правил.

Не добавлять «разумные» правила выбора тарифа, если они отсутствуют в действующем M-коде/формулах. Такое изменение требует отдельного решения.

## 2. Расчетный запрос

### Входы и масштабирование плеч

| Поле | Значение сейчас | Ограничение baseline |
|---|---|---|
| Плечи | До 5 строк в Excel | В веб-интерфейсе — произвольное число плеч, без потолка в 5; для сверки с Excel использовать сценарии из 1–5 плеч |
| Тип ВС | Код на каждом плече | Сейчас ручной ввод |
| Аэропорт вылета / посадки | IATA-коды | Сейчас ручной ввод |
| Загрузка пассажиров | Число на каждом плече | Сейчас ручной ввод |
| Сценарий ЛЧ | Например `ГБ 2026`, `Оперативная 2026` | Выбирает значения М1/М2/М3 из конфигурации |
| Источник стоимости ГСМ | `ЦРТ` или `АК` | Выбирает ветку стоимости топлива |
| Техстоп | Нет либо номер одного плеча | Поддерживается не более одного; в модели хранить `null` или идентификатор плеча, без привязки к его позиции |
| Бортпитание | `Включено` / `Не включено` | Влияет на переменную часть питания |

Плечи вводятся вручную: пользователь добавляет и удаляет строки по необходимости. В будущем они могут поступать через API, но это не меняет расчетный контракт: API должен сформировать те же поля, что сегодня вводятся на `РАСЧЕТ!S:V`.

### Режимы реализации

| Режим | Назначение | Правило |
|---|---|---|
| Совместимость с Excel | Тест и сверка | Повторять актуальные M-коды, порядок строк и формулы; сравнение проводится на сценариях до 5 плеч |
| Целевой веб-интерфейс | Рабочая эксплуатация | Применять ту же логику к любому числу плеч; итог — сумма результатов всех строк |

## 3. Использование и обновление источников

### Интерфейс «Источники»

В интерфейсе должен быть отдельный экран со всеми подключенными источниками. Для каждого источника пользователь может:

- видеть назначение, текущий путь, маску/тип файла, дату и статус последней загрузки;
- открыть исходный файл и результат его парсинга для просмотра;
- добавить новый файл или обновить существующий; файл сохраняется в директорию, заданную для этого источника;
- вручную запустить обновление одного источника или всех источников;
- увидеть ошибки загрузки и последнюю успешно использованную версию данных.

В параметрах должны настраиваться пути источников. Путь не должен быть зашит в коде: для него хранятся идентификатор источника, директория, правило выбора файла (например, маска `7480_srv`), тип парсера и статус доступности. Это позволяет использовать прежние директории Power Query либо изменить их без доработки приложения.

### Операционный workflow

1. Пользователь открывает «Источники», просматривает актуальные файлы или результаты предыдущего парсинга.
2. Пользователь добавляет/обновляет `7480_srv.xlsx` или `реестр.xlsx`; интерфейс сохраняет файл в директорию, заданную в конфигурации соответствующего источника.
3. Пользователь запускает обновление одного источника либо всех источников. Парсеры строят новый снимок данных по тем же правилам, что и Power Query.
4. Пользователь на странице «Подключённые услуги» при необходимости добавляет отсутствующую услугу/аэропорт вручную.
5. На главной странице пользователь вводит плечи и параметры; расчет сразу пересчитывается по актуальному снимку данных.

Обновление источников и расчет — отдельные операции. Расчет должен быть воспроизводим по зафиксированному снимку загруженных данных, версии файлов и курсу валюты.

### Версия активных данных

После успешного обновления одного/нескольких источников, а также после добавления
или удаления ручной услуги, система увеличивает номер активной версии данных.
Этот номер возвращается вместе с каждым результатом расчета и виден на главной
странице. Он позволяет однозначно зафиксировать, на каком текущем наборе
тарифов, маршрутов и ручных дополнений получен результат. Полная история
снимков и восстановление старой версии — отдельная следующая функция, не
подменяемая этим номером.

### Power Query `ЦРТ_Check`: тарифная таблица

Входы: последний по дате изменения файл с маской `7480_srv` в настроенной директории, а также сохраненные ручные записи справочника услуг.

Подтвержденные правила активного M-кода:

- сохраняются услуги: `АНО АД`, `АЭРОВОКЗАЛ`, `АЭРОВОКЗАЛ(М)`, `БУКСИРОВКА`, `ВЗЛЕТ-ПОСАДКА`, `ВОДА`, `ЗАПРАВКА ВС`, `КЕРОСИН`, `ОБЕСПЕЧЕНИЕ МАСЛАМИ ТН`, `ПАССАЖИР`, `ПАССАЖИР(М)`, `ПРИЕМ-ВЫПУСК`, `САНУЗЕЛ`, `СЛИВ ВОДЫ`, `ТЕЛЕТРАП МИН`, `ТРАНСПБЕЗОП`, `ТРАНСПОРТ`, `ТРАП`, `УБОРКА`, `БОРТПИТАНИЕ`;
- допускаются пустой тип ВС и типы `733`, `737`, `738`;
- исключаются строки без ставки;
- для `КЕРОСИН` остается одна строка по аэропорту: максимальная ставка, затем при равенстве — по `В/С`, затем по наиболее поздней дате начала;
- для `AER` применяются заданные в M-коде правила максимальной ставки для отдельных услуг и типов ВС;
- формируется ключ `Сцепка = АП + "-" + Услуга`;
- в конец результата добавляются ручные записи справочника услуг.

### Единый справочник «Подключённые услуги»

В веб-интерфейсе отдельный лист `ЦРТ+` не переносится. Распарсенные из файлов тарифы и ручные дополнения отображаются вместе на странице **«Подключённые услуги»**.

- У каждой строки обязателен признак происхождения: `из файла` или `добавлено вручную`; для импортированной строки показываются файл-источник и версия загрузки.
- Пользователь может добавить вручную аэропорт, услугу и ставку, если ключ `АП-Услуга` отсутствует среди распарсенных данных. Такая строка сохраняется отдельно от файлов, отображается как ручная и не удаляется при последующих обновлениях источников.
- Ручная строка не является override существующего импортированного тарифа. Для совместимости порядок расчета — сначала распарсенные строки, затем ручные: при одинаковом ключе `VLOOKUP`-совместимый выбор оставляет первой импортированную строку.
- Если после нового парсинга появляется импортированная строка с ключом ручного дополнения, обе записи сохраняются, а интерфейс показывает конфликт. Ручная строка не удаляется автоматически; результат расчета использует импортированную строку до отдельного согласованного решения.

### Power Query `Реестр`: цена керосина

`реестр.xlsx` очищается, из поля вида цены выделяется аэропорт, а цена приводится к RUB:

- RUB → коэффициент 1;
- USD → актуальный курс ЦБ РФ из XML ЦБ на момент обновления;
- затем используется `MAX(Цена RUB)` по аэропорту.

Это правило максимальной цены по аэропорту утверждено для текущего baseline и должно быть воспроизведено без добавления фильтра по дате рейса, поставщику или иному атрибуту.

### `Выгрузка 1С`

Это почти исходная распарсенная детализация реестра керосина: партнер, вид цены поставщика, номенклатура, валюта, период, цена. Она предназначена для анализа и не участвует напрямую в формулах себестоимости.

## 4. Конфигурация

| Конфигурация | Источник Excel | Роль в расчете |
|---|---|---|
| Характеристики маршрутов | `ИШР` | Время полета, расстояние, расходные показатели и налет |
| Признак линии | `Признак МВЛ` | Определяет `МВЛ` / `ВВЛ` по аэропортам |
| Сценарии ЛЧ | `Справочники!L:P`, `СценарийРасчетаЛЧ` | М1/М2/М3 по версии сценария и типу ВС |
| Множитель АНО | `Справочники!F:G` | Используется в расчете АНО по типу ВС |
| Прочие расходы | `Прочее` | Ставка для строки `ПРОЧЕЕ` по аэропорту |
| Дополнительные тарифы | `ЦРТ+`, `ЦРТ_pls` | Только отсутствующие в выгрузках ключи |
| Источники и пути | Папки Power Query и маски файлов | Настраиваемые пути, правило выбора файла, парсер, версия и статус загрузки |
| Константы формул | `РАСЧЕТ`, `НО`, `Прочее` | Включая `2.7`, `1666.6`, `500`, `6×1500`, нормы услуг и фиксированные ставки |

Конфигурация не должна быть захардкожена в коде. Для baseline ее значения обязаны быть версионируемыми и сохраняться вместе со снимком расчета.

## 5. Алгоритм расчета одного плеча

Для каждого плеча последовательно вычислять:

1. `routeKey = departureIata + "-" + arrivalIata`.
2. Найти налет `flightTime` по `routeKey` в `ИШР` (аналог `РАСЧЕТ!E`). При отсутствии совпадения действующий Excel возвращает `0` через `IFERROR`.
3. `fuelTons = flightTime × 2.7` (аналог `F`).
4. Определить признак линии: если хотя бы у одного аэропорта флаг МВЛ, то `МВЛ`, иначе `ВВЛ` (аналог `W`).
5. Подготовить строковые ключи наземных услуг `departureIata + "-" + service` и подобрать ставки из `ЦРТ_Check`.
6. Рассчитать ГСМ, наземное обслуживание, АНО, питание, НДС и затем М1/М2/М3.

### Выбор ставки из `ЦРТ_Check`

Excel использует `VLOOKUP` по единственному ключу `АП-Услуга` и возвращает первое совпадение по физическому порядку таблицы. В таблице есть дубли ключа, поэтому для текущей эквивалентности необходимо сохранять порядок результата M-кода и применять «первое совпадение». Позднее это правило может быть заменено отдельной согласованной моделью приоритетов.

### ГСМ и заправка

| Условие | Правило |
|---|---|
| `fuelSource = АК` | `цена РеестрКер по аэропорту вылета × fuelTons`; отсутствие цены дает `0` |
| `fuelSource ≠ АК`, обычное плечо | Сумма строк `КЕРОСИН` и `ЗАПРАВКА ВС` нормального блока `НО` |
| `fuelSource ≠ АК`, плечо-техстоп | Сумма строк `КЕРОСИН` и `ЗАПРАВКА ВС` техстоп-блока `НО` |

### Наземное обслуживание и АНО

Для нормального плеча детальная матрица `НО` рассчитывает услуги по формуле `объем × ставка`. В итог `H` включается сумма нормального набора услуг от `ВЗЛЕТ-ПОСАДКА` до `ПРОЧЕЕ`; услуги `КЕРОСИН`, `ЗАПРАВКА ВС` и `АНО АД` выводятся в отдельные компоненты.

Для техстопа применяется отдельный набор услуг. В `H` попадает сумма `АНО`-исключающего техстоп-блока.

`АНО = ставка(АП-АНО АД) × множитель типа ВС + расстояние / 100 × 1666.6`.

### Бортпитание и НДС

- Если маршрут равен `-`, питание равно `0`.
- Иначе питание включает постоянную часть `6 × 1500`.
- При `бортпитание = Включено` дополнительно прибавляется `пассажиры × 500`.
- НДС равен `10% × (ГСМ + НО + АНО + питание)`, только если линия `ВВЛ` и в паре аэропортов присутствует `DME`, `SVO` или `VKO`; иначе `0`.

### Уровни маржи и итог

По выбранному сценарию ЛЧ и типу ВС берутся три ставки из `СценарийРасчетаЛЧ`:

`marginN = scenarioRateN × flightTime × 1000`, где `N ∈ {1, 2, 3}`.

Для каждого N:

`totalMarginN = ГСМ + НО + АНО + питание + НДС + marginN`.

Итог расчета — значения `ИТОГО М1`, `ИТОГО М2`, `ИТОГО М3` по каждому плечу и сумма по всем введенным плечам.

## 6. Главная страница расчета

Главная страница полностью функциональна и интерактивна: пользователь вводит любое число плеч, параметры каждого плеча и применяет те же управляющие параметры, что в текущем мониторе:

- сценарий ЛЧ;
- источник стоимости ГСМ (`ЦРТ` / `АК`);
- выбор единственного техстопа;
- включение/выключение бортпитания.

Компоненты себестоимости по плечам — ГСМ, НО, АНО, бортпитание, НДС, М1, М2 и М3 — должны быть доступны и участвовать в расчете всегда. Экран предоставляет переключатель детализации: пользователь может скрыть эти компоненты и оставить компактный режим с вводом плеч и итогами. Скрытие влияет только на отображение, не на формулы, состав услуг или результат.

## 7. Текущие ограничения и будущее расширение

- Поддерживается один техстоп. Модель данных должна допускать последующее расширение до нескольких, но baseline-интерфейс и расчет используют один.
- Плечи вводятся вручную и не имеют ограничений по количеству. Автоматический API-источник — последующее расширение.
- `ЦРТ_МВЛ` пока не реализован и не входит в исполняемый baseline.
- Экономическая методика, лежащая за М1/М2/М3, не переносится в этот модуль; монитор использует утвержденные сценарные значения.

## 8. Правила проверки эквивалентности

Перед любыми улучшениями требуется доказать совпадение с Excel на контрольных сценариях.

Минимум сравнивать:

- нормализованную таблицу `ЦРТ_Check`, включая порядок строк;
- `РеестрКер` и используемый курс/дату ЦБ;
- по-плечевые компоненты ГСМ, НО, АНО, питания и НДС;
- М1, М2, М3 и финальные `ИТОГО М1/М2/М3`;
- обычный сценарий, сценарий `АК`, сценарий с техстопом, питание включено/выключено и отсутствие найденной ставки/маршрута;
- экран «Подключённые услуги»: сохранение ручной строки после обновления источника и отображение конфликта с новой импортированной строкой;
- расчет из более чем пяти плеч: совпадение по каждому плечу с тем же одиночным/пятистрочным Excel-сценарием и верная сумма по всем строкам.

Любое отличие сначала фиксируется как расхождение baseline. Новое бизнес-правило вводится только после его утверждения, а не как неявная «поправка» к Excel.
