# Монитор расчета себестоимости — reverse engineering

Дата исследования: 2026-08-27. Исходные Excel-файлы открывались только для чтения; обновление запросов, изменение формул и сохранение книг не выполнялись.

Уровни уверенности:

- **Confirmed** — подтверждено формулами, M-кодом Power Query, метаданными книги или структурой данных.
- **Likely** — сильная интерпретация технических фактов, но бизнес-смысл не подписан явно.
- **Unknown** — определить по файлам нельзя.

## 1. Executive Summary

**Подтвержденное название:** «Монитор расчета себестоимости». Это калькулятор себестоимости цепочки из пяти рейсовых плеч: по каждому плечу рассчитываются три итоговых значения `М1`, `М2`, `М3` и их общая сумма. В используемой цепочке расчета нет отдельной сущности «груз»; поле `Вид груза` присутствует лишь в сырых источниках тарифов и в текущий расчет не попадает.

Фактический конвейер выглядит так:

`7480_srv.xlsx` + ручные дополнения `ЦРТ+` → таблица тарифов `ЦРТ_Check` → по-плечевые матрицы `НО` → лист `РАСЧЕТ`.

Параллельно `реестр.xlsx` → `РеестрКер` → стоимость керосина на `РАСЧЕТ` при выборе сценария `АК`. При обновлении этого потока Power Query обращается к сайту ЦБ РФ за текущим курсом USD.

`7480_nad.xlsx` является обязательным входом активного Power Query, но его строки фактически не попадают в итоговую таблицу: запрос помещает отсутствующее поле `Ставка` в `null`, а затем отбрасывает все строки без ставки. Это **Confirmed**. На текущем этапе перенос должен воспроизводить M-код как есть; любые изменения роли NAD — отдельная будущая доработка.

Утвержденный источник для программной реализации: [business-logic baseline](cost-monitor-business-logic.md). Он фиксирует ответы владельца процесса и имеет приоритет над прежними техническими неоднозначностями этого документа.

## 4. External Sources

### `7480_srv.xlsx` → тарифы `ЦРТ`

**Confirmed:** активный запрос `ЦРТ_Check` ищет самый новый `.xlsx`-файл, имя которого содержит `7480_srv`, в UNC-папке:

`\\nord.local\mow\Otdel\Общая\Департамент управленпия сетью и доходами\Шаблоны для отчетов\Выгрузки\ЦРТ`

Запрос читает `Sheet1`, проверяет 10 обязательных колонок, нормализует типы, оставляет выбранные услуги, пустые/`733`/`737`/`738` в поле `В/С` и непустую ставку. Результат получает ключ `АП-Услуга`, затем загружается в `ЦРТ_Check`.

| Источник | Данные | Место использования | Последующий расчет |
|---|---|---|---|
| `7480_srv.xlsx` | `АП`, `Услуга`, `Ставка`, единица измерения, терминал, коды ТС/ВС, даты действия, организация | Power Query `ЦРТ_Check` → `ЦРТ!A:K` | `НО` ищет ставку по ключу `АП-Услуга`; `РАСЧЕТ` получает сумму через `НО` и отдельно использует ставку АНО |

### `7480_nad.xlsx` → текущий эффект отсутствует

**Confirmed:** `ЦРТ_Check` загружает самый новый файл по маске `7480_nad`, проверяет наличие колонок `АП`, `Услуга`, `Тип`, `Надбавка/скидка`, затем приводит его к структуре SRV. Но при выборе колонок запрашивается `Ставка`, которой в NAD нет; создается `null`. Последующий шаг оставляет только строки со `Ставка <> null`.

Следствие: все строки NAD исключаются до формирования `ЦРТ`. В текущем активном коде надбавка/скидка не маппится на ставку и не применяется к SRV. По решению владельца процесса M-код является источником истины для этой логики: при текущем переносе это поведение воспроизводится без новых интерпретаций.

Старый незагружаемый запрос `Запрос1` использует NAD иначе — лишь чтобы получить список допустимых аэропортов для фильтрации SRV. Другой текущей ссылки на NAD не найдено.

### `реестр.xlsx` → цены керосина

**Confirmed:** есть два самостоятельных запроса к реестру.

| Запрос | Преобразование | Выход | Использование |
|---|---|---|---|
| `Реестр` | Пропускает 8 служебных строк, удаляет пустые столбцы, выделяет аэропорт из поля вида цены, переводит USD/RUB в рубли и агрегирует `MAX(Цена RUB)` по аэропорту | `РеестрКер` (`Реестр керосин!A:B`) | `РАСЧЕТ!G2:G6`, если `Y2 = "АК"` |
| `Выгрузка 1С` | Пропускает служебную шапку и оставляет шесть детальных колонок | `Выгрузка_1С` (`Выгрузка 1С!A:F`) | Аналитическая детализация, почти исходная версия распарсенного реестра; прямых потребителей среди формул нет |

`Реестр` использует UNC-путь, а `Выгрузка 1С` — путь `M:\...\реестр.xlsx`. Это два разных технических адреса одной ожидаемой выгрузки; их фактическая эквивалентность нужно подтвердить.

### Веб-источник ЦБ РФ

**Confirmed:** запрос `Реестр` вызывает `https://www.cbr.ru/scripts/XML_daily.asp`, выбирает USD, получает последнюю опубликованную дату курса, применяет курс к USD-ценам и принимает RUB как 1. Отдельная функция `fnGetCurrencyRate` тоже умеет получить исторический USD-курс по дате, но другие запросы ее не вызывают.

## 5. Data Flow

### Ветка аэропортовых тарифов

```text
7480_srv.xlsx
        ↓
Power Query «ЦРТ_Check»: фильтрация услуг/типов ВС, правила КЕРОСИН и AER
        ↓
ручная таблица «ЦРТ_pls» добавляется в конец результата
        ↓
таблица «ЦРТ_Check» на листе «ЦРТ»
        ↓
«НО»: VLOOKUP по ключу АП-Услуга, количество × ставка
        ↓
«РАСЧЕТ»: ГСМ/наземное обслуживание/АНО
        ↓
итоги М1, М2, М3
```

### Ветка цен керосина

```text
реестр.xlsx
        ↓
Power Query «Реестр»: очистка, извлечение аэропорта, конвертация USD/RUB
        ↘ CBR XML (актуальный USD)
        ↓
MAX(цены в RUB) по аэропорту → «РеестрКер»
        ↓
«РАСЧЕТ»: цена × ГСМ тонн, только при Y2 = «АК»
```

### Справочно-расчетная ветка

```text
«ИШР» (маршрут/налет) → «РАСЧЕТ» (время полета и ГСМ)
«Признак МВЛ» → «РАСЧЕТ» (МВЛ/ВВЛ) и «ЦРТ_МВЛ»
«Справочники» + «Прочее» → «НО» и «РАСЧЕТ»
```

`ЦРТ_МВЛ` не является частью используемого потока: на листе 240 сохраненных ошибок `#REF!`, а формулы `РАСЧЕТ` и `НО` не ссылаются на него.

## 7. Business Logic

### 7.1 Подготовка используемых тарифов

**Входы:** SRV, NAD, ручная таблица `ЦРТ_pls`.

**Логика:** `ЦРТ_Check` выбирает допустимые услуги и типы ВС, оставляет непустые ставки, формирует ключ `АП-Услуга`, применяет специальные правила для керосина и AER, затем добавляет `ЦРТ_pls`.

**Выход:** таблица `ЦРТ_Check` с 11 полями на листе `ЦРТ`.

**Особые правила, подтвержденные в M-коде:**

- по керосину остается одна строка на аэропорт: максимальная ставка; при равенстве — по `В/С`, затем наиболее поздней дате начала;
- для аэропорта `AER` по шести услугам оставляется максимальная ставка; для части услуг также фиксируется предпочитаемый тип ВС (`738` либо `737`);
- NAD загружается, но фактически исключается из результата из-за отсутствия маппинга `Надбавка/скидка → Ставка`.

**Используется дальше в:** `НО`, а через него — на `РАСЧЕТ`.

### 7.2 Маршрут и налет

**Входы:** аэропорты вылета/посадки на `РАСЧЕТ`, справочник `ИШР`.

**Логика:** строится ключ маршрута `IATA-IATA`; `РАСЧЕТ!E` получает `ИШР!P` — налет в десятичных часах. В `ИШР` сам ключ, часы, минуты и налет вычисляются из полей IATA и времени полета.

**Выход:** время полета `E`, расход ГСМ в тоннах `F = E × 2.7`.

**Excel-реализация:** `РАСЧЕТ!B:C,E:F`; `ИШР!A,N:P`.

### 7.3 Стоимость ГСМ и заправки

**Входы:** `F` (ГСМ тонн), `Y2` (сценарий), `РеестрКер`, матрица `НО`, `ПлечоТС`.

**Логика:**

- при `Y2 = "АК"`: цена керосина аэропорта вылета из `РеестрКер` × тоннаж;
- иначе: берутся суммы `КЕРОСИН` и `ЗАПРАВКА ВС` из соответствующей нормальной или техстоп-матрицы `НО`;
- техстоп определяется по значению `Z2` через named cell `ПлечоТС`.

**Выход:** `РАСЧЕТ!G`.

### 7.4 Наземное и аэронавигационное обслуживание

**Входы:** `ЦРТ_Check`, тип ВС, IATA, пассажирская загрузка, `Прочее`, расстояние из `ИШР`.

**Логика:** на `НО` для каждого из пяти плеч строится блок услуг: ключ `АП-Услуга`, объем, ставка из `ЦРТ`, сумма `объем × ставка`. Нормальная итоговая строка складывает услуги `ВЗЛЕТ-ПОСАДКА` … `ПРОЧЕЕ`; отдельный техстоп-блок содержит свой набор услуг. АНО считается отдельно как тариф `АП-АНО АД` × коэффициент типа ВС + `расстояние / 100 × 1666.6`.

**Выход:** `РАСЧЕТ!H` (наземное обслуживание) и `I` (АНО).

**Excel-реализация:** `НО!A3:AM39`; `РАСЧЕТ!H:I`.

### 7.5 Бортпитание и НДС

**Входы:** маршрут, число пассажиров, `AA2`, тип линии, аэропорты.

**Логика:** бортпитание равно нулю для `маршрут = "-"`; иначе содержит постоянную часть `6 × 1500` и, только если `AA2 = "Включено"`, переменную часть `пассажиры × 500`. НДС равен 10% суммы `ГСМ + НО + АНО + питание`, только при точном условии: линия `ВВЛ` и один из аэропортов — `DME`, `SVO` или `VKO`; иначе ноль.

**Выход:** `РАСЧЕТ!J:K`.

**Business-смысл условия НДС:** Unknown; техническая формула подтверждена.

### 7.6 М1 / М2 / М3 и итог по плечу

**Входы:** `X2`, тип ВС, время полета, таблица `СценарийРасчетаЛЧ`, G:K.

**Логика:** `L`, `M`, `N` — три значения из сценарной таблицы по версии ЛЧ и типу ВС, умноженные на налет и на 1 000. Каждая итоговая колонка `O`, `P`, `Q` суммирует ГСМ, НО, АНО, питание, НДС и соответственно М1, М2 или М3.

**Выход:** итог на каждое плечо и строка `ИТОГ`.

**Подтверждено владельцем процесса:** М1, М2 и М3 — уровни получаемой маржи. Их экономическая детализация не является спецификой данного монитора и остается в зоне ответственности экономистов. `ГБ 2026`, `Оперативная 2026`, `ЦРТ`, `АК` и подобные значения — сценарии расчета, позволяющие выбирать разные источники данных, включая годовой бюджет и фактические данные авиакомпании.

### 7.7 Важное ограничение выбора тарифа

**Confirmed:** `НО` использует `VLOOKUP(ключ, ЦРТ!A:D, 4, 0)` — только по ключу `АП-Услуга`. При этом в текущем `ЦРТ` 4 077 строк, 2 480 уникальных ключей, а 646 ключей имеют дубликаты. Даты действия, тип ВС, терминал, организация и единица измерения не участвуют в этой Excel-формуле.

Следовательно, Excel берет первое совпадение в физическом порядке таблицы. Подтвержденное решение для текущего этапа: воспроизводить все приоритеты, выраженные в активном M-коде Power Query, и сохранять итоговый порядок результата для эквивалентности `VLOOKUP`. Новые правила поверх M-кода не вводить; если в дальнейшем для конкретного случая правила окажется недостаточно, его уточняют отдельно.

**Основной пользовательский результат:** лист `РАСЧЕТ`, строки 2–6 — пять плеч, строка 7 — `ИТОГ`.

## 13. Excel-specific Logic

- UI параметров реализован через прямой ввод ячеек, Data Validation и named ranges вместо отдельной конфигурационной модели.
- Техстоп выбирается текстом вида `2. BAX-HMA`, а номер извлекается формулой `LEFT(...)`; это технически хрупкая связь с форматом отображения.
- Детализация пяти плеч реализована пятью горизонтальными повторяющимися блоками на `НО`, а не одной нормализованной таблицей `leg × service`.
- Поиск тарифа — `VLOOKUP` по составному текстовому ключу; он не выражает условия срока действия, типа ВС и приоритета.
- Формулы содержат бизнес-константы и ручные ставки: `2.7`, `1666.6`, `500`, `6×1500`, количества `1/2/90`, фиксированную ставку пожарной машины и формулы на `Прочее`.
- `ЦРТ+` добавляется в конец таблицы, но предназначен только для отсутствующих в выгрузках услуг/аэропортов, не для override существующей ставки. Новая система должна валидировать это ограничение.
- `ЦРТ_МВЛ` пока не доработан и содержит 240 `#REF!`; он исключен из текущей исполняемой логики, но остается отдельной будущей веткой.

## 14. Migration-relevant Findings

### Data Layer

- Хранить сырые версии SRV, NAD и реестра с датой загрузки/версией файла.
- Хранить конфигурацию каждого источника: путь директории, маску выбора файла, тип парсера, время обновления и статус последней попытки.
- Хранить тариф как запись с аэропортом, услугой, ставкой, единицей, ВС, терминалом, датами действия и организацией — не только строковым ключом.
- Отделить актуальный курс ЦБ и дату курса от цены поставщика; предусмотреть воспроизводимое сохранение использованного курса.

### Transformation Layer

- Перенести подтвержденные M-преобразования как версионируемые pipeline-правила.
- Перенести активный M-код как эталон текущего поведения, включая существующий эффект NAD и порядок результатов.
- Зафиксировать тестовыми наборами результаты M-кода и «первого совпадения» Excel, прежде чем менять правила выбора тарифа.
- Объединить импортированные и ручные дополнения в один справочник услуг с признаком происхождения; ручная запись сохраняется при обновлении файлов и не становится override импортированной ставки.

### Business Logic Layer

- Выделить расчет по одному плечу как параметризуемую функцию: маршрут, тип ВС, пассажиры, источник ГСМ, единственный техстоп, питание, версия сценария.
- Сохранить раздельные группы: маршрут/налет, ГСМ, наземные услуги, АНО, питание, НДС, М1/М2/М3.
- Вынести жестко заданные коэффициенты и объемы услуг в конфигурацию с владельцем и датой действия.

### Configuration / Parameters Layer

- Отдельно хранить сценарии ЛЧ, нормы услуг, флаги МВЛ, ручные прочие расходы, специальные правила AER и типы ВС.
- Дать пользователю интерфейс настройки путей источников вместо привязки к жестко заданной сетевой папке Power Query.
- Ограничить валидными справочниками те параметры, которые сейчас вводятся вручную без validation: тип ВС, IATA, пассажиры, `AA2`.

### Presentation Layer

- Сохранить сущность «плечо», но не переносить потолок из пяти горизонтальных Excel-блоков: веб-форма должна принимать произвольное число плеч.
- Сделать интерактивными все действующие ручки расчета: сценарий ЛЧ, источник ГСМ, техстоп и бортпитание.
- Отображать отдельно итоговые KPI и детальную раскладку услуг/источников; детализацию компонентов можно скрыть без изменения расчета.
- Добавить экраны «Источники» (просмотр, загрузка, обновление, ошибки) и «Подключённые услуги» (импортированные и ручные тарифы в едином справочнике).

Первые тесты программной реализации должны точно воспроизводить текущие результаты Excel. Требования целевого веб-интерфейса — управление источниками, единый справочник услуг, неограниченное число плеч и скрываемая детализация — зафиксированы в [business-logic baseline](cost-monitor-business-logic.md) и реализуются без изменения расчетных правил.

## 15. Unknowns

- Экономическая детализация уровней маржи М1/М2/М3 намеренно остается вне границ монитора; ее ведут экономисты.
- Бизнес-смысл специального условия НДС для `DME`/`SVO`/`VKO` не раскрыт в файле и не уточнялся.
- `ЦРТ_МВЛ` — будущая, пока не завершенная ветка; ее окончательный источник и правила еще не определены.
- Поведение процесса при недоступности сетевой папки или ЦБ РФ, а также фактическая эквивалентность UNC- и M:-путей не установлены.
- Для будущей автоматической загрузки плеч через API еще не определен контракт источника, полей и момент обновления.
